# 隔离、完整红线、产物与路径

## 参与者之间的隔离

| 角色 | 拿什么 | 不拿什么 |
|---|---|---|
| 执行 session | 提示词文件（共享说明 + 执行部分）、落点全表 | 别的修法建议 |
| 审核 session（`review` / `audit`） | 共享说明、检查问题、文件范围 | 执行报告、执行者的自评 |
| codex 复核 | 需求、共享说明、改动本身 | 执行报告、Claude 这边的任何结论 |

执行者和审核者不得改共享说明；发现说明和裁定或源码对不上，写进报告，由主会话核过再改。

## 红线

| 想这么做的时候 | 为什么不行 |
|---|---|
| 「文档 / 注释 / memory 里写了它是这样的」 | 不是事实来源。回源码核，写出 `file:line`。 |
| 「这个模块我大概知道里面有什么」 | 没读完就不写。读完整个模块再写设计。 |
| 「报告说第 N 行有问题」 | 自己打开那一行看，再写最小复现。 |
| 「代码读了好几遍，没问题」 | 没跑场景，就不算审过。 |
| 「先跑一遍，看看结果再说对不对」 | 预期必须先写。 |
| 「改完了再补测试」 | 测试在改动前写、先在旧代码上看结果。改完再补的测试只会贴着实现写。 |
| 「把先写的测试改一下就过了」 | 先写的测试不为迁就实现而改；改了要写理由，codex 审核会看。 |
| 「修好了，相关测试绿了」 | 还要撤回即失败，并按 checklist F 组过一遍影响面。 |
| 「重构没改行为，不用 A/B」 | 没有 A/B 对照，"没改行为"只是自称。 |
| 「这条报的问题很具体，直接修吧」 | 具体不等于真实。没复现，就不算确认。 |
| 「顺手把这个边角问题也修了」 | 边角进待办。 |
| 「给执行 session 口头讲一下背景就行」 | 必须读同一份存了盘的说明。 |
| 「多派几个角色或子代理，审得更全」 | 换人设盲点不变，还慢。要换视角就换模型，要更全就补检查问题、场景和测试。 |
| 「这个之前报过吗？不确定，再报一次」 | 先查 `待办.md` 和问题总清单。已排期的说成已排期。 |
| 「改的是一条原则，先改最明显的两处」 | 先盘点全部落点，再写提示词。 |
| 「再跑一遍完整 CI 稳妥些」 | 完整 CI 30–43 分钟，整件事只跑一次；中途只跑相关检查。 |
| 「审出一处漏改的，补上就行」 | 说明盘点不完整，先补全盘点。 |

## 产物与路径

| 产物 | 位置 |
|---|---|
| 提示词、报告 | 桌面 `~/Desktop/Habitus/experiments/<日期>-<条目>/`（不放仓库，另开的 session 也读得到）：`提示词.md`（一份，分部分）、`报告.md`、`codex-复核.md` |
| 复现脚本、A/B 基线产物、对抗测试记录 | 同一实验目录的 `scripts/`、`out/`（`baseline/`、`verify/`）；只留最终产物，过程副本跑完即删，不整份复制盘面 |
| 只读输入 | 数据集 `~/Desktop/Habitus/datasets/`，跑数检查点与录好的模型答案 `~/Desktop/Habitus/runs/`，留作对照的最终盘面 `~/Desktop/Habitus/results/`；索引见 `~/Desktop/Habitus/README.md` |
| 问题总清单、待办、处理进度 | `~/Desktop/Habitus/notes/`（`38-README核对问题清单.md` 新一轮开一节；`待办.md` 记边角与范围外的发现） |
| 设计决定（编号裁定） | 以仓库 `docs/rulings/README.md` 为准。代码里的「裁定 N」都能在仓库那份查到，架构测试 `tests/architecture/test_rulings_documented.py` 守着 |

实验进行中按模板记录预期、结果、偏差。结论连同关键数字与数据版本写进裁定、`待办.md` 或 notes 之后，过程目录可删；删目录之前，结论与证据必须已经落到这些长期位置。Habitus 的数据只放桌面 `~/Desktop/Habitus/` 这一个目录。
一次性脚本不进仓库。git 操作全部由用户自己做。
