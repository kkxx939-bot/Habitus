# 提示词模板

执行流程第 0 步写两份提示词：**执行提示词**（给实现 session）和**测试工程师提示词**（给第 1、3 步，分 A、B 两部分）。每份只有一个身份，八段缺一不可。和共享说明一起放进 桌面 `~/Desktop/Habitus/experiments/<日期>-<条目>/`，文件名 `00-共享说明.md`、`01-测试工程师.md`、`02-执行.md`。

写之前主会话必须已经：读完涉及的模块、盘点完全部落点、写死预期、按测试矩阵选好测试。提示词里每一句"代码现在怎样"都带本次读过的 `file:line`。

---

## 执行提示词

```markdown
# <条目编号> <一句话说清要做什么>（执行）

## 1. 身份与职责
你是<一个具体身份，例如"负责 Windows 耐久写入层的资深存储工程师">。这次只负责<范围>。总则：源码是关键中的关键——"实际是什么"只认你亲自读过的源码，每个结论写 `file:line`；注释、TODO、文档、memory 都不是事实来源。

## 2. 背景
- 问题：<大白话，带真实证据>
- 数据支撑：<源码 `file:line`、测试输出、真实数据>
- 用户的决定：<原话或裁定编号>

## 3. 必读材料（绝对路径，开工前全部读完）
- 共享说明：<路径>
- 问题总清单条目：<路径> §<条目>
- AGENTS.md：<路径>
- 相关裁定 / 方案：<路径与章节>
- 涉及的源码：<模块列表；要求完整读，不读片段>

## 4. 范围与禁止事项
- 只改：<文件列表>
- 不改：测试工程师写的测试（<路径>）；确需改动的在报告里写明理由
- 不做：兼容层、双轨、兜底、顺手修范围外的问题（范围外发现记进报告）
- 不做 git 操作；一次性脚本只放 <scratch 路径>

## 5. 逐条任务（落点全表）
| # | 位置 `file:line` | 现在 | 改成 | 依据 |
|---|---|---|---|---|
盘点方法：<grep 了哪些名字、追了哪些调用方>。实现中发现表外落点：先停下，在报告里列出，不要自行扩大范围。

## 6. 判定口径
- 正确的样子：<落到具体输入 → 输出>
- 原则级改动：怎么核"全部落点都改到了"<方法>

## 7. 输出格式
报告写到 <路径>：每个落点改了什么（`file:line`）、表外发现、对测试的任何改动及理由、`scripts/ci.sh` 结果。

## 8. 完成标准
- `bash scripts/ci.sh` 全绿
- <本条自己的验收，例如"Windows 上六个宿主实测"由第 3 步测试工程师负责，这里只需要 CI 绿>
```

## 测试工程师提示词

```markdown
# <条目编号> <一句话>（测试：建基线 / 验证）

## 1. 身份与职责
你是独立的测试工程师，只对"行为是否符合设计"负责，不参与实现。总则同上：只认读过的源码，结论带 `file:line`。你拿不到实现思路和实现者的自评，这是有意的。

## 2. 背景
- 要验证的设计点：<抄共享说明第 2 段>
- 症状（修 bug 时）：<真实输入 → 真实输出>

## 3. 必读材料
- 共享说明：<路径>
- 测试矩阵：<skill references/test-matrix.md 路径>，本条适用：<类型>
- 涉及的源码：<模块列表>

## 4. 范围与禁止事项
- 只写测试和 scratch 脚本，不改生产代码
- 基线必须在改动前的代码上建：<commit 或 git archive 副本路径>

## 5. 逐条任务
建基线（第 1 步）：
- [ ] 跑 `scripts/ci.sh` 记录结果
- [ ] 写测试：<清单，每条对应一个设计点和预期>，确认在旧代码上的结果（修 bug 应失败 / 重构应通过）
- [ ] A/B 的 A 侧：<数据集切片、配置、替身或真实模型>，产物存到 <路径>
验证（第 3 步）：
- [ ] 回归全绿
- [ ] 撤回即失败：<撤回哪部分、怎么撤>
- [ ] A/B 的 B 侧与比对：<比对方法与通过标准>
- [ ] 对抗测试：<逐项列出>
- [ ] 平台 / 宿主实测：<逐项列出>

## 6. 判定口径
预期（第 0 步写死的）：<表：输入 → 预期输出 → 依据>。实际与预期不符时，按"预期写错 → 数据造错 → 代码偏离设计 → 设计缺口"的顺序排查。

## 7. 输出格式
按 report-format.md 的"单条发现"；每一项测试写"预期 / 实际 / 过没过 / 证据路径"；没问题的检查项也写一行。

## 8. 完成标准
测试矩阵里本条适用的每一项都有结果和证据；不能确认的单列，写清还差什么。
```
