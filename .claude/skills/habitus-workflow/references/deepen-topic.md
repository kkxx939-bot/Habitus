# 深化题目（`deepen` 模式）

用户提出一个新方向或新题目（例如"把夜间跑批全部换成实时"），在写方案、改题目、派任何人之前先走这一步。用户 2026-11-08 定的要求原话：

> 我想要的是一个更深入的版本，而不是一个更大的版本。在重写题目之前：
> 1. 请说明该领域的顶尖专家会做哪些我没有要求的事情
> 2. 请列出他们会从哪些最原始的素材入手，而不是我已经整理好的素材
> 3. 请列出他们会使用的具体方法和工具
> 4. 除了你我之外，还有什么可以证明结果是正确的？
> 然后请修改我的题目，使其完全符合上述要求

**更深，不是更大**：深化是把同一个题目问到根上（真正要解决什么、怎么才算对），不是往里加新的模块、新的功能、新的范围。改写后的题目范围不得比原题大；想加的东西写成"不在本题"一行。

## 四问怎么答（落到 Habitus）

| 问 | 要写出什么 | 不算数的答法 |
|---|---|---|
| 1 顶尖专家会多做什么 | 点名领域（例如流式计算 / 增量统计 / 作业调度 / 序贯检验），写出该领域里做这类题目必做、而用户没说的事：先定正确性口径（什么叫"实时版和批量版结果一致"）、先量现状再动、先定失败与重放语义、先定可观测指标 | "考虑性能""注意边界"这类空话 |
| 2 最原始的素材 | 不是桌面整理过的观察文档、不是旧报告，而是：源码本身（`file:line`）、盘上真实数据（账本、行为树、关系表、检查点）、每次模型调用的原始输入输出（`logs/对话/`）、调用流水与资源读数、金标数据集、裁定原文、引用的论文原文 | 拿 `主会话观察.md`、memory、子代理转述当起点 |
| 3 具体方法和工具 | 写到能直接执行的粒度：剖析（cProfile / tracemalloc / py-spy）、在检查点副本上离线重放、A/B 对照（旧批量 vs 新实现逐字段比）、性质测试、复杂度推算再实测验证、对照文献算法 | "用测试验证" |
| 4 除了你我还有什么能证明对 | 独立于实现者和主会话的证据：真实数据上旧版与新版产出逐项对齐（例如同一检查点重放 N 天，关系表 / 机会表 / 预期逐条 diff）；金标与 v0.12 预期表；另一模型（codex）独立复核；撤回即失败；用户在真实宿主上的实测 | "CI 绿了""我读过代码" |

## 输出

1. 四问的回答（每条落到 Habitus 的具体文件、数据、裁定，带 `file:line` 或数据路径；没核过的标"待核"）。
2. **改写后的题目**：一段话，写清真正要解决的问题、正确性口径、验证方式、不在本题的东西。
3. 交用户确认。用户确认之后才进入 `plan`（写方案）或 `change`（执行）。

改写后的题目和用户的确认原话，存进这一条的进度文件或方案文档开头。
