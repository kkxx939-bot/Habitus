# 跨模型复核（codex）

## 为什么用另一个模型

让同一个模型扮演不同角色，它的盲点不会变：一个人设漏掉的，另一个人设大概率也会漏掉。换一个模型，盲点才真正不同。所以第二视角交给 codex，而不是再派一个 Claude 子代理。

## 给它什么

- **只给**：共享说明、文件范围、检查问题清单。
- **不给**：Claude 这边任何审核者的报告、主会话的判断、疑似问题列表。给了它，它就会去确认这些结论，而不是独立找问题。

## 命令

只读运行，结果写到文件：

```bash
codex exec \
  -m gpt-5.6-terra \
  -s read-only \
  -C /Users/gulf/PycharmProjects/Habitus \
  -o <scratch>/review/<日期>-<范围>/codex-report.md \
  - < <scratch>/review/<日期>-<范围>/codex-prompt.md
```

- 模型用 `gpt-5.6-terra`（中档、均衡；用户 2026-11-02 定：太弱的模型看不出效果），**不开 fast**。`~/.codex/config.toml` 里的默认 `gpt-6.1-sol` 在当前 ChatGPT 账号下报 `model_not_found`，所以必须显式写 `-m`。codex 额度用完时，等额度重置后再用；确实不可恢复时，改用本机 Claude Code CLI 的 sonnet，并在汇报里写明这次复核换了模型。
- `-s read-only`：保证它不改任何文件。

## codex-prompt.md 的写法

```markdown
你是独立的代码审查员，只读，不改任何文件。

先读共享说明：<共享说明的绝对路径>。所有判断以其中第 2 段（设计原文）和第 3 段（正确的样子）为准。

审查范围：<文件列表>

逐条回答 <checklist.md 的绝对路径> 里 <维度> 的检查问题。

输出格式：<report-format.md 的绝对路径> 里的「单条发现」。没有问题的检查项也要写一行「已查，未见问题」。
```

## 回来之后怎么用

只看两边**不一致**的地方：

| 情况 | 处理 |
|---|---|
| 两边都报了同一个问题 | 正常进入独立复现 |
| 只有一边报了，另一边明确查过同一处 | 重点核对，交给复现者 |
| 只有一边报了，另一边没查到这一处 | 正常进入独立复现 |
| 两边对同一处的判断相反 | 主会话对着裁定原文判断；判断不了的交给复现者 |
