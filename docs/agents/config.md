适用：改 `habitus/config/**`，或给任何领域加可调参数时读。

# 配置

## 唯一边界

- `habitus/config/` 是唯一的外部配置边界。`HabitusConfig` 从 `HABITUS_CONFIG_FILE` 指向的单一严格 YAML 加载：未知字段、重复键和宽松类型一律拒绝；不保留 JSON 或分散环境变量的兼容入口。
- 配置只在启动时读一次，不做运行中热更新。
- 模型服务的秘密值只写在这份 YAML 的 `credentials` 段（具名凭据注册表），各路由用 `credential_ref` 引用；该文件及其备份必须保持 0600；其余各段不得出现秘密值（用户 2026-10-23 定，取代"只从环境变量取"）。
- 跨领域的容量关系在组装前统一校验。各领域 Config 是内部强类型值对象；不得再建并行的配置加载入口或重复的上限。

## 可调参数

- 会随部署规模、模型成本、存储容量或等待策略变化的运行参数，必须通过 `habitus/config/` 进入主链，不得作为运行路径里的散落常量。
- 领域 Config 类型与它的行为实现放在同一领域模块；`habitus/config/` 只负责严格聚合和 YAML 构造。禁止为了集中目录而让领域模块反向依赖配置组合根。
- 统一示例 YAML（`habitus/config/example.yaml`）必须完整列出当前全部可调字段，不能把可调默认值藏在 Python 构造器里。现有可调字段与默认值以它为准。
- 上限和预算类配置是保护闸：数值和当前模型不匹配时重定数值或加一条自洽校验，不删闸。
- 新加门槛给固定默认值并写明依据（逻辑下限、现行值或文献），不用合成数据调出来。

## 不可配置的代码不变量

- Schema 字段、URI/目录结构、page_id 范围、CAS/revision、MERGE/DELETE 资格、Links/Backlinks 一致性和事务发布顺序不做成配置。
