# 目录概览与助手查记忆

## 目录 L0/L1：`memory/semantic`（裁定 110、112）

- 按模板拼出，不调模型。
- L1：每张直接 L2 卡片一行（文件名、创建与更新时间、版本、一小段说明），说明取哪个字段由四类 Schema 的 `overview_line` 声明；每个子目录一行（名字与项数）。超出条数或字数上限时只列最新的，并写明还有多少张没列。L0 是确定性的一行"目录：N 项"。
- 按受影响目录链自下向上刷新；生命周期维护每次按模板全树重建一遍补齐。
- 不得读取 Conversation、决定 L2 内容或执行长期记忆合并。
- 模板概览渲染在 `infrastructure/tree/overview.py`，只给卡片目录用；根目录概览只列四类卡片的目录，检索清单显式只往卡片目录走。
- 概览里的时间与版本只给系统算冷热，不给模型看。
- 没有向量库、向量索引、Embedder、Reranker；不得以兼容层、可选分支或旁路缓存恢复。

## 查询：`memory/retrieval`（裁定 110、111）

- 公共入口只有 `SearchService.search()`，按"清单 → 挑 → 找 → 判"：
  - 清单：读各目录模板概览、按冷热排序；退休的不列，最冷一档单列、只给名字。
  - 挑：调一次模型，按问题、清单和当前对话的活跃摘要与最近消息（只用于补全指代）决定读哪些卡片、要不要按日期与关键词查每一轮的记录和会话摘要；最冷那组每次最多一张。
  - 找：不调模型。读完整 L2 并按 Links/Backlinks 有界补一跳；按日期列、按关键词搜每一轮的记录（只搜名字、目标、概要、步骤、原始名字段，空白记录不算）；按日期与关键词找会话摘要（命中词数相同时近的在前）；都有条数与天数上限。
  - 判：调一次模型，只输出用到的材料编号，系统按编号拼上下文；不够最多再走一轮。
- 会话摘要第一轮就能查。材料矛盾以时间更晚的为准，每条材料带时间。
- 每一轮的记录经检索包里只收发纯值的只读接口读，实现放在 `runtime`；记忆代码不引用行为代码。
- 会话摘要的日期目录是对话身份；按日期找时用摘要里的起止时间换算成配置时区。
- `kinds` 只限定清单给哪几类；`limit` 限定最终交出的卡片数。
- 整次查询（含"被用到"的记账）不超过 `memory.search_service.time_limit_seconds`，到点交出已找到的、不返回空；记账拿不到锁就跳过这次并写观测。
- 模型不可用时只交出档案并写明原因，不得以关键词匹配顶替"挑"和"判"。清单读不出时照常查另外两处并说明（没有提交窗口内的拒读）。
- 语义判断（该查哪里、两条是不是一件事）归模型；代码只做结构校验；关键词搜只执行模型给出的检索词。
- 不得复活旧通用 Context、Catalog、FTS、Vector、Query 链；检索层不引入租户、另一套后台队列或旧数据兼容。关系候选只属于 Memory Editor。
