# 行为侧、语义树、预测层

适用：改 `habitus/behavior/**`、`habitus/scene/**`、`habitus/foresight/**`、`habitus/series/**`、`habitus/temporal/**`、`habitus/conditions/**`、`habitus/runtime/generation*`、`habitus/runtime/scene*`、`habitus/runtime/foresight*`、`habitus/runtime/model_queue*`、`habitus/runtime/habit_cards.py`、`habitus/runtime/relation_cards.py`、`habitus/runtime/reminder_records.py`、`habitus/runtime/record_files.py`、`habitus/runtime/behavior_records.py` 时读。

设计以 `docs/rulings/README.md` 的编号裁定为准；下面只列不变量，细节（默认值、字段、步骤实现）以代码与 `habitus/config/example.yaml` 为准。

## 词表（裁定 101）

- 两条 lane 各一份固定的初始词表，加用户自己长的节点。
- 每条记录调一次模型选一个词：会话 lane 在融合里选、结果随判断存；物理 lane 在归约里选。
- 没有待定池、每晚新增、定期拆改和迁移。
- 节点转在用、退出、删除在换代里数，纯计数，不调模型。
- 词表文件（`kinds.state.json`、`kinds.md`）在这一支树外的 `behavior/<lane>/`，不是树上的节点。

## 范围与原料

- 行为层只跟踪一个主体；旁人的行为，乃至"旁人在场"，都不记。主体判断上指向旁人判断的关系直接剪掉。
- 判重（同一件事被看成两条）只在融合层做。归约的同地址加序号后缀只是保命阀并打 `original_name` 标记，下游只认标记、机械跳过计数，不做判重判断。
- 行为侧原料（观测、判断、作业）在归约发布后释放，生命周期由消费决定，不设保留期。

## 事件与空白（裁定 112）

- 每一支一个只看得到自己那支的视图 `BehaviorTree(树根, lane=支)`，全程同一个实例；"哪一支"进路径和地址，不进文档字段。
- 只增：只由归约经只增写入器原子新建（生产代码里只有归约的 runner 引用它，架构测试守着）；建立时间由外面给，版本恒为 1。
- 归约的 sweep 锁按支派生，脏日由归约直接记。
- 行为每天的模型概览已删；事件与空白的目录不生成 L0/L1，不参与冷热、不淘汰、不压缩。
- 浏览与提取时的三个只读动作、助手检索的清单都只认卡片目录（显式限定），卡片不连到事件。
- 预测拍、结算、诊断按出处取行时，带 `://` 的出处必须解析成一支里的事件地址（空白的地址也不行），否则报错，不当"找不到"。
- 行为侧关着时不建事件与空白两个目录；先开后关的原样留着、不读、不报错。

## 三类只做记录的卡片（裁定 113、115）

习惯卡片 `habits/<lane>/<词的编号>.md`、提醒记录 `reminders/<lane>/YYYY/MM/DD/<预期的编号>.md`、关系卡片 `relations/<lane>/<前因>/<后果>--<段>[--<条件摘要>].md`：

- 系统写、只做记录。不是长期记忆（不进四类枚举、不经提取、不参与冷热和淘汰、不调模型，助手的检索、浏览、提取时的只读动作都查不到）；也不是事件或空白（不进那两类枚举、不经只增写入器）。
- 预测、语义树、归约的任何计算都不读它们（架构测试守着）。
- 目录第一次写时才建：语义树没开就没有 `habits`、`relations`；预测没开就没有 `reminders`。
- 习惯卡片只由换代的"习惯卡片"一步写。
- 提醒记录只由包在账本四个写方法与出口写取走记录外面的那一层写：从账重算，取走那一段由出口传进来，按记录一把最里面的锁，写失败不让写账失败，没有整份重建的入口。
- 关系卡片只由换代的"关系卡片"一步照盘上最晚那张关系表写：
  - 只写跨代带着的行（候选、成立、失效、前向未复现）与退休的行，不写每代重算的"检验过没过"。
  - 一张表都读不到时一张都不删。
  - 行没了：成立过的留着标结束，从没成立过的删。
  - 退休行保持旧读数；重新当候选时"以前成立过"留在卡片上。
  - 文件名是关系的纯函数（条件换成摘要）。
  - 指向后果的关系目录与习惯卡片的地址是普通字符串，不进 `links`/`backlinks`。
  - 和语义树工作目录里存关系表的 `<scene_root>/<lane>/relations/` 同名不同根。

## 按支装配（裁定 102）

- 语义树与预测层按 lane 各装一份：`<scene_root>/<lane>/`、`<foresight_root>/<lane>/`；锁、租约、完成标记、模型队列状态各支一份。
- 预测 Worker 与模型队列 Worker 各一个，每一槽依次做两支（会话在前）；一支的失败只算这一支的。
- 提醒的出口共用一个，账按支记。

## 换代（裁定 96、97、98、99、101、113、115）

- 换代取代原来的夜线 Job Worker 与它的 Job 账；没有自己的 Worker，也没有换代租约，在预测 Worker 每个槽边界、预测拍之前做。
- "同一根同一天只换一次"由预测根租约加完成标记保证。进程起来第一次看换代时，先撤回上一次中途被杀剩下的重试项。
- 做今天这一代的条件（全部满足）：今天的完成标记还没有；当地今天不早于最晚一份完成标记的日子；定稿日从最早一天连续到昨天；预测拍水位过了 max(今天零点, 最后一段跨过零点的「未观测」的结尾) 再 `foresight.generation_margin_slots` 槽（今天白天合盖写的空白不让等待重来，裁定 99）。
- 步骤顺序固定：重读放假数据 → 重试收尾（不试，只推日子、丢弃、撤回）→ 结算 → 读序列 → 数在用的词 → 语义树（同步词表 → 封口：生成刚封口那天的命中记录与日历情境、盖日完成章 → 按缓存折叠关系，含关系行退休，裁定 98）→ 机会表（含单元历史与压实）→ 当天的日子预期 → 习惯卡片 → 关系卡片 → 完成标记 `<scene_root>/<lane>/generation/<日期>.json`。
- 换代里没有模型调用。
- 必须成的步：读序列、机会表、日子预期、完成标记。没成就是今天没有这一代、不写标记，同一天按 `scene.generation_retry_*` 退避一直重试；退避只在进程里，重启后从头。
- 其余各步尽力而为：失败要报出、走退路、计数，这一代照常写完，同一天不重做。习惯卡片、关系卡片两步只做记录、尽力而为、不在语义树写锁里。
- 换代那一刻对话熔断开着，关系表就沿用上一代。
- 锁被另一进程拿着是还没准备好：这一槽到此为止，不算失败、不退避。
- 完成标记存在，这一天就不再做；标记坏了明确报错，不当做过、也不当没做。
- 结算认"那天有没有这一代"只读完成标记的三值；旧的夜线 Job 账与 `last_run.json` 不读、不迁移。
- 换代复用领域无关的锁、原子文件与退避原语，不复用 MemoryJob 本体。

## 模型队列（裁定 97、108）

- 调模型的活（出错重试就近试、物理一支未封口判断的选词、先验混合问法）都在模型队列 Worker 里一项一项做。
- "还欠什么"每一轮从盘上现算，不记账；先验在今天这一代完成之后才算欠着。
- 换代在做时队列在两项之间停下。

## 预测拍（裁定 99）

- 预测拍对齐槽边界，把跑到哪一刻、上一次建预期看到哪一刻落盘为水位。
- 两拍之间隔了超过 `foresight.unwatched_tolerance_slots` 槽，就把中间那段交会话一支写成「未观测」空判断，由归约落树。
- 预测拍不等今天这一代：建预期用盘上最晚一张做完了的机会表，多旧都用；今天这一代做成后下一拍换用今天的表。
- 旧表下的日子预期只为表那一晚之后一次都没再出现过的类建。

## 预测层的分工（裁定 114）

- `foresight` 包只放纯规则：不碰 infrastructure、不读 `series.reader`（架构测试守着）。账本、单元历史、机会表、出口状态的读写与"取材料 → 调纯规则 → 落账"的流程在 `runtime/foresight_*`。
- loss 尺子只量、不当门：递送那一拍算出的单元读数与这条预期那本账的读数随递送落盘（可空的 `loss_readings`，没有就是"没量到"）；除了编解码与算分（`foresight/loss.py`）没有代码读回（架构测试守着）；每次结算之后从账上现算，不存累计值。

## 观测

- 每代一个 span、每步一个子 span，模型队列每项一个 span；写指标与 INFO 日志；每代写报告文件（含关系表双向变化、换代时各类还欠几项、结算那一节的 loss；没写成的也写）与本地 trace 文件。
- 按行为的 loss 明细只留本地，不进 span；span 属性只放计数、固定枚举与受控原因码。
- 健康面读：换代的最近结果、卡住的日子、日期回退、下一次重试时刻与最新完成标记；模型队列的循环存活、积压与跨过换代的欠账；三种模型能力的熔断（开着时写出给人看的原因）与长期记忆跳过的段；系统时区与配置时区的偏移。
